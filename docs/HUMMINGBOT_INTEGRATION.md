## Что выяснилось по реализации

1. У hbot уже есть управление одним ботом на установку и JSON-вывод. Это кандидат на границу Telegram-управления, но до выбора проверяем обработку ошибок, статусы и способ вызова. Нельзя подставлять пользовательский ввод в shell-команды.
2. Grid Strike сейчас направленный: side BUY/SELL. Он создаёт executor при нахождении цены внутри диапазона. Это не готовая точная копия формы Bybit.
3. GridExecutor рассчитывает количество уровней из spread, бюджета и минимального размера заявки. Явного параметра N в рассмотренной конфигурации нет. Геометрический режим в ней также не представлен.
4. Есть early_stop(keep_position=True). Это полезный механизм сохранения актива, но нужно проверить весь путь CLI/controller → executor → отмены → итоговые остатки. Значение по умолчанию False нельзя считать нашим поведением.
5. limit_price=0 отключает соответствующий stop-out в конфигурации executor. Triple-barrier TP/SL/time-limit и остальные пути завершения проверяются отдельно; одного флага недостаточно для гарантии «никогда не ликвидировать автоматически».
6. Модели используют Decimal, однако в _generate_grid_levels есть преобразования в float для ceil/floor. Ранее краткая характеристика «расчёты через Decimal» неполна. Нужны граничные тесты до принятия округления.
7. Там же комментарий про 20% запас соседствует с множителем 1.05. Это конкретная неточность upstream-комментария, пока не исправленная.
8. В оркестраторе есть сохранение executors и чтение исторических результатов. Это ещё не доказательство восстановления активной сетки после аварии без повторных ордеров; нужен отдельный сценарный тест.
9. Binance Spot и perpetual имеют свои user-stream modules и тесты. Переписывать коннекторы с нуля не планируем.

Обновлено решением владельца: WSL не используется. Сборка и проверки будут на тестовом VPS. Выполнена первая очистка и добавлена маршрутизация Spot Testnet; актуальные действия и статус в [Testnet runbook](TESTNET_RUNBOOK.md).
