## 1. Hummingbot

- [Репозиторий](https://github.com/hummingbot/hummingbot), лицензия Apache-2.0 по скачанному LICENSE.
- [GridExecutor](https://hummingbot.org/strategies/v2-strategies/executors/gridexecutor/) поддерживает Spot и perpetual; в исходниках присутствуют Binance Spot и Binance Perpetual connectors.
- Проверен `controllers/generic/grid_strike.py`: диапазон, общий quote-бюджет, направление, Decimal, ограничения числа активных заявок, keep_position.
- Проверен путь остановки в `hummingbot/strategy_v2/executors/grid_executor/grid_executor.py`: early_stop с keep_position, условия stop-loss/limit-price.
- Есть инфраструктура обработки заявок и тесты GridExecutor; наличие тестов не означает, что они запущены нами.

Расхождения: Grid Strike — направленные входы с выходами через take-profit, а не доказанная точная копия биржевой двусторонней сетки. Количество уровней определяется параметрами spread/минимального размера; наша форма N и геометрическая сетка требуют проверки и, возможно, изменения контроллера. keep_position сам по себе не доказывает требуемое сохранение всей стратегии при выходе за диапазон и восстановлении.

Что адаптировать: Telegram-мастер, понятный статус, остановку без ликвидации, диапазон с автовозобновлением, точную семантику сетки и бюджета. Нельзя оставлять настройки стратегии по умолчанию: в просмотренном контроллере есть leverage=20 и keep_position=False. Полноценную Telegram-форму из наших требований не проверяли.

Вердикт: первый кандидат на прототип как готовая инфраструктура Spot/Futures. Сначала проверяем объём адаптации стратегии; не объявляем его готовым аналогом Bybit.

## 2. jordantete/grid_trading_bot

- [Репозиторий](https://github.com/jordantete/grid_trading_bot), MIT по LICENSE.txt.
- Python, CCXT, арифметическая/геометрическая сетки, backtest, sandbox, SQLite.
- В коде есть `core/order_handling/placement_journal.py`, стабильные clientOrderId, обработка неизвестного результата в live execution, recovery/reconciliation и соответствующие тестовые файлы.
- Ручной stop в документации отменяет ордера и сохраняет актив; это близко к согласованному поведению.
- Telegram-уведомления через Apprise не равнозначны Telegram-управлению.

Обнаруженные ограничения:

1. [Going Live](https://github.com/jordantete/grid_trading_bot/blob/ed516f95f54c90f8d0d8d3eee98d9bfa4fc40952/docs/usage/going-live.md) прямо сообщает, что simple_grid и hedged_grid ещё не работали с реальным капиталом.
2. `OrderStatusTracker` опрашивает статусы ордеров; WebSocket котировок не означает наличие private WebSocket исполнений.
3. `GridManager` и `PendingPlacement` используют float для цен/количеств; необходима проверка округления и точности.
4. Live-режим предполагает выделенный аккаунт и стартует с биржевыми остатками. Наш выделенный бюджет внутри аккаунта потребует адаптации.
5. Готовая поддержка Futures с позициями, маржой и funding при просмотре не подтверждена. Название hedged_grid не является доказательством фьючерсного хеджирования.
6. Нужна проверка PnL комиссий в третьем активе и поведения при ошибках восстановления учёта.

Вердикт: содержательная основа для Spot и источник готовой реализации; нельзя обещать небольшую Telegram-обёртку и готовность к реальным деньгам без дополнительной проверки.

## 3. 51bitquant/binance_grid_trader

- [Репозиторий](https://github.com/51bitquant/binance_grid_trader), MIT по LICENSE.
- Есть реальные файлы Spot/Futures стратегий и Binance gateways, GUI и headless entrypoints.
- В SpotGridStrategy имеются границы, grid_number, фиксированный order_volume, реакции на исполнение и ограничение активных заявок.
- Последний скачанный commit датирован июнем 2026, поэтому некорректно называть проект просто заброшенным.

Ограничения: README ориентируется на Python 3.7; requirements содержит PyQt5 5.15.2 и старые закреплённые зависимости. В стратегии float, конкретная проверка минимальной суммы 10, учёт ордеров в словарях; состояние сохраняется в JSON. Telegram-мастер и доказанное восстановление незавершённых операций требуют отдельной работы. Полной проверки всех gateway/recovery-путей не проводили.

Вердикт: близкий функциональный пример Spot/Futures, но модернизация может оказаться дороже адаптации Hummingbot.

## Следующая проверка перед выбором основы

Для Hummingbot и компактного Spot-кандидата сравнить на одинаковом сценарии:

1. Конфигурация диапазона/N/бюджета и фактически созданный стартовый набор ордеров.
2. Исполнение, повтор события и таймаут после принятия заявки.
3. Перезапуск с открытыми и уже исполненными заявками.
4. Выход/возврат в диапазон без продажи активов и повторной стартовой закупки.
5. Ручное завершение с отменой только принадлежащих боту заявок и сохранением активов.
6. Отделение бюджета бота от остальных средств и совпадение отчёта с фактическими остатками.

Результат — конкретный перечень доработок готовой основы. Писать новый торговый движок до этой проверки не требуется.
